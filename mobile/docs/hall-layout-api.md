# Редактор зала и backend-dev

Проверено по `origin/backend-dev`, коммит `3cf14eb`.

Вход в редактор: «Зал → Изменить» или «Ещё → Залы». Изменения до сохранения хранятся только в редакторе. Чтение списка залов возвращает схему, чтение столов — положение, форму, места, `rotationDegrees`, `enabled`.

`PUT /api/v1/restaurants/{restaurantId}/halls/{hallId}/layout` принимает:

```json
{
  "layout": {
    "canvasWidth": 1200,
    "canvasHeight": 800,
    "items": [
      {"type":"BAR","positionX":900,"positionY":100,"width":180,"height":500}
    ]
  },
  "tables": [
    {"id":"existing-table-uuid","number":"1","seatsCount":7,"shape":"ROUND","positionX":60,"positionY":40,"rotationDegrees":90,"enabled":true}
  ]
}
```

Ответ: `{hall, tables}`. Общий запрос атомарно сохраняет интерьер и **существующие** столы. Мест 1–12, формы ROUND/SQUARE/RECTANGLE, поворот столов 0/90. Интерьер BAR/WINDOW/ENTRANCE/WALL/COLUMN/PLANT. Поворот прямоугольного предмета сохраняется перестановкой ширины и высоты: отдельного поля поворота у предметов нет.

Новые столы создаются отдельным `POST /halls/{hallId}/tables` при нажатии «Сохранить», затем включаются в PUT. Создание новых столов вместе с остальным планом не атомарно: если PUT завершится ошибкой, созданные столы уже останутся в БД. Клиент заменяет временные ID на серверные сразу после каждого успешного POST, очищает undo и при повторе не создаёт их заново. Ошибка явно сообщает о частичном результате. При потере ответа POST клиент не может гарантировать отсутствие дубля: серверный idempotency key отсутствует.

Удаление существующих столов, переименование, скрытие и изменение порядка залов пока не реализованы в контроллерах этой ветки, хотя некоторые маршруты перечислены в API.md. Эти действия не отправляются и не имитируются клиентом. Существующий стол можно выключить через `enabled=false`.

Клиент проверяет пересечения столов, номера, места и границы. Backend проверяет права, принадлежность столов залу, дубли ID, места, поворот и ограничения БД, но отдельного полного валидатора пересечений и ошибок `violations` для плана в этой версии нет.
