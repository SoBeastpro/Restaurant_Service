# Сверка спринта с backend-dev

Ветка: backend-dev, исходный коммит 3cf14eb. Рабочие правки фронтенда перенесены с main без потерь; ранее удалённый demo.js не восстановлен.

## Реально реализовано на сервере

- Чтение ресторана, залов и включённых столов сотрудниками.
- Схема зала (`canvasWidth`, `canvasHeight`, `items`), атомарное обновление существующих столов; 1–12 мест, поворот и выключение стола.
- Получение текущей смены директором и менеджером через **GET /api/v1/me/current-shift**. Указанный в API.md `/restaurants/{id}/shifts/current` фактически отвечает 400: маршрут не реализован, запрос попадает в `{shiftId}`.
- Старт смены с одним сотрудником без столов, изменение состава и назначений активной смены.
- GET `/restaurants/{id}/team`: директор, менеджер, сотрудники и приглашённые.
- Приглашение существующего аккаунта, сохранённая зашифрованная строка приглашения, перевыпуск.
- Новые токены в `tokens` ответа POST /restaurants.
- Общий секрет внутренних API и автоматическая передача его межсервисным клиентом.

## Что подключено на фронтенде

- Реальный контракт схемы и чтение сохранённого плана. Новые столы создаются POST, затем сохраняются вместе с планом; частичные ошибки не скрываются.
- /team, роли и статусы приглашений, срок действия, QR, копирование только токена, перевыпуск. Приглашения, созданные старым seed без зашифрованного токена, требуют перевыпуска один раз.
- PUT участников текущей смены вместо создания новой; сохранение назначений и изменение закреплений во время смены.
- Серверная история стола с именами участников команды; реальный отчёт закрытия смены.
- Немедленная замена onboarding-токенов после создания ресторана; выход на экран входа после смены пароля.
- Обновление Зала, Смены, Задач, Команды и стола при открытии. Сбои загрузки показываются и не маскируются выдуманными столами или сотрудниками.
- Параллельное чтение независимых данных, таймаут сети и объединение параллельных обновлений JWT.
- План/секции у управляющего и очередь/план у сотрудников; готовые столы свёрнуты в счётчик. Официант может сообщить проблему своего стола.

## Что действительно остаётся на backend

- Атомарное создание новых столов вместе с планом и идемпотентность POST.
- Реальные маршруты удаления столов, переименования/скрытия залов, полная проверка пересечений и `violations`.
- История стола доступна только директору/менеджеру. Фронтенд не предлагает её сотруднику, пока сервер не разрешит чтение.
- В текущем ответе /me нет membershipId; для официанта личные столы берутся из current-shift.assignedTableIds. Имена других участников сотруднику не доступны через /team.
- Системный администратор реализован отдельными platform API, но мобильного административного интерфейса нет. Общая статистика, деньги, шаблоны, план дня и сброс пароля не включены в этот спринт.
